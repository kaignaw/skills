## 3. 数据是怎么整理出来的

1. **DXF**：`工程做法明细.dxf` 为 AutoCAD 2004 ASCII DXF，GBK/ANSI_936 编码，文字在图层 `图名、说明`，共 206 条 TEXT。按图面三栏（X≈3k–16k / 22k / 39k）和 Y 降序还原为“室外装修—屋面/外墙”“室内装修—地面/楼面/踢脚/墙裙/内墙/天棚/吊顶/油漆”的做法树。
2. **清单**：从 GB/T 50854-2024 附录 A~R 提取全部 472 条清单编码、名称、特征、单位、规则、工作内容；再合并江苏〔2025〕第 12 号公告增补的 5 条，形成 477 条清单主表。每条都记录原文页码；472 条用官方 PDF 的 OCR 文本逐行比对编码、页码和名称后标 `已核对`，5 条公告增补按附件核对。
3. **定额**：先用 `pdftotext -layout` 提取官方 815 页 PDF 文本，解析出 3133 个唯一子目（编号/名称/章/节/单位/工作内容/物理页码），写入 `quota_2026_jiangsu.csv`。解析脚本为 `scripts/build_quota_index.py`，处理了计量单位上标换行、节标题被表格数字行误识别、多行工作内容漏抓、多栏名称压缩等 PDF 文本问题；第二十章系数表以“子目”而非“编号”作表头，已单独解析补入 20-1～20-18，并逐条核对单位和计算基础。两个重建脚本都会按编码继承已有核对结论，重建不会把已核对行打回待核对。
4. **套用表**：按“清单组 + 多定额行”的方式生成 96 行，清单字段只在组首行填写，续行留空。所有“类推、换算、无对应、图纸残缺”均写入备注。
5. **校验**：用 `openpyxl` 检查无空缺单位/名称/编码格式，并生成五张工作表。

## 4. 主表的质量与复核

### 4.1 清单主表

`boq_2024_jiangsu.csv` 的定位是“清单主表 + 逐行核对状态”，字段为：

`序号 | 清单编码 | 清单名称 | 计量单位 | 附录 | 节 | 表号 | 项目特征 | 工程量计算规则 | 工作内容 | 数据来源 | 江苏差异 | 核对状态 | 核对方式 | 核对人 | 核对日期 | 核对批次 | 原文页码 | 原文摘录 | 证据ID | 备注`

- **已核对 477 条**：472 条按官方 PDF OCR 逐行比对（编码 + 页码 + 名称），5 条江苏增补按公告附件核对，证据见 `data/verification_evidence.csv`。
- **核对边界**：机器比对确认编码、页码、名称一致；项目特征、计算规则、工作内容仍由网页表格重建，可能受换行、上标丢失、跨页合并影响，专业使用前应结合图纸判断。
- **复核工具**：`scripts/verify_boq_from_ocr.py --ocr gbocr.json --recheck-legacy --apply` 可重跑 OCR 比对；`--dry-run` 只报告不写文件。
- **江苏增补 5 条**：逐条取自江苏〔2025〕第 12 号公告附件，国标没有对应编码。
- **单位补正**：部分原文上标丢失（如 `m` 实为 `m³`/`m²`），已按同条“工程量计算规则”补正并在备注注明；`010506016~010506021` 单位为跨行合并单元格 `t`，网页文本未抓到，已按同表钢筋项目补正。
- **附录 H 补正**：网页全文缺“附录 H 门窗工程”标题和 H.1 节标题，且 H.2 带有伪字符 `╱`；已按官方 PDF 目录补为“附录H 门窗工程”“H.1 木门”“H.2 金属门”。
- **江苏差异**：R 类记录标注“高层/超高层施工措施费不单独列项；另增补 011601016~011601019”；5 条增补项标注“江苏增补；GB/T 50854-2024 无此清单编码”。

查询方式：

```bash
python3 scripts/lookup.py boq 屋面
python3 scripts/lookup.py boq 保温 --chapter 附录K
python3 scripts/lookup.py boq --status 待核对 --limit 50
python3 scripts/lookup.py boq 011101001 --json
```

重建主表（需要 GB/T 50854-2024 全文 HTML 和 `beautifulsoup4`；默认按编码继承已有核对结论）：

```bash
python3 scripts/build_boq_index.py --html 50854.html
```

### 4.2 定额主表

`quota_2026_jiangsu.csv` 是唯一的定额主表，不是“官方名称库”的替代品。它的字段为：

`序号 | 定额编号 | 定额子目名称 | 计量单位 | 章 | 节 | 页码 | 工作内容 | 数据来源 | 核对状态 | 核对方式 | 核对人 | 核对日期 | 核对批次 | 原文摘录 | 证据ID | 备注`

使用边界：

- **已核对 3133 条（100%）**：77 条为历史人工复核（第二十章超高降效 18 条，页 733，单位 `%`，计算基础人工费；另有 59 条项目复核）；3056 条按官方 PDF 的表格线与文字坐标逐列还原表头比对（`核对方式` = “官方PDF表格线逐列核对（机器）”）。
- **核对的含义**：证明该编号所在列的表头层级、计量单位与主表一致，并补齐主表漏掉的层级；不证明项目特征、构造做法、消耗量已复核。组价前仍建议按 `页码` 回查。
- **463 条按表头补级改名**：原主表名称缺级（多为构造/材料层级），已按表头顺序补齐并保留原顺序；逐条对照见 `data/quota_name_review.csv`。跨列合并表头偶尔会让某行多带一个上级标签，属于需要抽复的点。
- **100 条单位为“见表”**：原表单位在表头或附表中，未能稳定提取，备注会提示回查。
- **73 条工作内容为空**：多为五金、配件表、说明表或第二十章系数表；原表没有“工作内容”行，备注会提示（系数表改注降效系数和计算基础）。
- **316 条同名提示**：同一名称对应多个子目（不同厚度、规格、施工方式等），备注会提示“同名子目，需按页码/项目特征区分”。
- 页码是 **PDF 物理页码**，不是书刊印刷页码；用 PDF 阅读器跳到该页即可复核。

查询方式：

```bash
python3 scripts/lookup.py quota 保温
python3 scripts/lookup.py quota 干挂 --chapter 第十三章
python3 scripts/lookup.py quota 10-61 --json
python3 scripts/lookup.py quota --status 待核对 --chapter 第十五章
```

按官方 PDF 逐列复核（需要 `pdfplumber`）：

```bash
pip install pdfplumber
python3 scripts/verify_quota_from_pdf.py --pdf js2026.pdf --report work/quota_pdf_report.csv   # 只出报告
python3 scripts/verify_quota_from_pdf.py --pdf js2026.pdf --apply                              # 写回主表 + 证据
```

脚本用表格边框线定位每个编号所在列，逐行还原该列的表头层级与单位；结论分“一致 / 可补全（补级改掉单位碎片）/ 冲突（交人工）”。这是与 `build_quota_index.py`（`pdftotext -layout` 整行切分）相互独立的第二条路径。

重建主表（需要官方 PDF 和 `pdftotext`；默认按编号继承已有核对结论）：

```bash
pdftotext -layout js2026.pdf js2026.txt
python3 scripts/build_quota_index.py --text js2026.txt
```

不要直接把 `待核对` 名称写进投标/结算成果；也不要把主表称为“官方全量名称数据库”。

### 4.3 覆盖率与待核对队列

```bash
python3 scripts/audit_coverage.py            # 覆盖率、证据完整性、重复编码、空字段
python3 scripts/audit_coverage.py --strict   # 未 100% 核对或有证据缺失时返回非零
python3 scripts/build_review_queue.py --out work/review_queue.csv
```

`build_review_queue.py` 把待核对条目分为 P0（字段/抽取异常：名称为空或过短、单位见表、工作内容为空、名称含单位碎片/独立数字）、P1（高频章节）和 P2（其他），用于安排人工核对顺序。

## 5. 数据范围与限制

- **清单主表 477 条已全部核对，但核对方式是机器 OCR 比对**：编码、页码、名称一致；项目特征和构造仍需结合图纸复核。新项目先用 `lookup.py boq` 查编码，再核项目特征。
- **定额主表 3133 条已全部核对，但核对方式是机器逐列比对**：证明编号、页码、名称层级、单位与原文一致；构造、工作内容、消耗量仍需按 `页码` 回查。`audit_coverage.py --strict` 会在出现 `待核对` 或缺证据时返回非零。
- **不是官方软件数据库**：编码和名称来自标准文本，实际组价时仍应以当地计价软件（GTJ/GCCP/江苏清单库）中的版本为准，注意勘误和地方补充规定。
- **不是自动套项结果**：`mapping_examples.csv` 是人工整理的示例，包含待确认项；不能不经复核直接作为投标/结算依据。
- **价格不在本技能范围**：本技能只做清单列项和定额子目匹配，不含人工、材料、机械单价、费率、税金、措施费。需要组价时，另接当地信息价和费用定额。
- **地方差异**：江苏各市在安全文明施工、材料基价、补充定额上可能有差异；涉及具体项目时，以项目所在地造价管理机构的口径为准。

